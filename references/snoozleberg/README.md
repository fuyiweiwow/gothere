## 为什么另存结构化记录

`study.json` 使用 `gothere.reference-study` 格式，记录的是研究证据，不是可导入编辑器的 `schemaVersion: 1` 关卡。它保留原始观察和设计解释的区别；不为缺少证据的部分编造坐标、点击时间、伤害条件或运行规则。

每条观察带视频秒数、片段类型和帧图引用；每组机制另列推断、未解问题、已有能力及能力缺口。以后确定某一段值得实现时，再把经过确认的关系转成普通关卡DSL。历史灰盒位于旧分支的 `src/experiments/levels.js`，不随本次资料归档进入主线，也不把我们的原创示例当成原作源码。主线可运行的参考关卡仍是 `src/editor/first-level.js` 中的屋顶里程碑。

## 文件如何保存

文档、时间索引和结构化记录纳入Git版本管理。完整视频与21张帧图保存在本项目 `references/snoozleberg/local/`，由 `.gitignore` 排除，不进入公开仓库或离线产品包。复制/备份整个项目时应同时保留这个目录；只克隆Git仓库不会取得媒体文件。来源页面仍保留，方便重新定位。

`study.json` 的 `localArchive` 列出大小和SHA-256，可检查本地录像是否为同一文件。关键帧拼图本身带采样时间；拼图序号不是连续播放的帧号。剪辑和失败蒙太奇不能当作同一次操作的连续因果。
