# 程序生成实验 · 0.20.0-experimental

实验分支：`codex/procedural-generation`。目的：用可编辑、可验证的候选减少空白页创作负担，保留环境干预和把握时机的核心。当前没有训练模型、调用模型服务或引入Rogue规则。

## 如何试用

构建本分支后打开 `dist/gothere-editor.html`，或启动开发服务器访问本地编辑器。右上「生成实验」输入种子，选择3～5次操作，生成最多3个机制序列不同的候选。候选预览与验证不会写入草稿；「导入编辑器」创建新草稿，「导入并演示解法」同时开始录制解法的回放。演示可暂停、单步、重置，返回编辑后正常编辑/手动运行。

默认里程碑继续保留，工作区修订号不变。生成对话框关闭或点取消会停止后续工作。离线HTML包含生成器，无网络和GPU要求。main的Pages稳定版不受此分支影响。

相同版本、种子、操作数量和变体号生成相同候选。种子保留原文，最大80字符，变体号单独输入算法；界面每批尝试变体1～8，去重后最多取3个。生成器版本更新后不保证旧种子产生原样布局，因此应导出JSON保存喜欢的结果。

## 组成与边界

| 片段 | 普通DSL中的机制 |
| --- | --- |
| 临时通路 | 行为启用surface，after停用；缺少承托时真实下落 |
| 延迟休息 | after准备，短暂inactive，再恢复active；接触仍按通用伤害能力 |
| 撤撑落物 | 停用支撑collider，body受重力下落，impact筛选实际撞击者后调用休息行为 |
| 两种效果 | 一次输入调用两个物体行为，分别铺路和让危险物休息 |

每段引用使用独立前缀。组合器安排平路、衔接坡面、起终点、速度、操作时间和恢复时长。3次操作取3种不同片段；5次会复用一种片段。变化来自机制顺序和空间参数，当前没有任意因果图、分叉路线、完整多层空间搜索或自动资源布景。候选的普通实体、行为、规则和坐标可在编辑器中修改；没有按生成关卡ID分支的执行逻辑。

片段由代码中的纯数据构建器定义，尚无用户可编辑/导出的模板库，也不从任意手工草稿自动学习机制。`src/generation/fragments.js`的接口包括事件源、关键位置、准备时间、实体、规则和路面。今后扩展片段必须提供约束和验证，不能只随机换贴图或加入不可见补丁。

## 验证到底证明了什么

每个候选在同一固定60 tick/秒内核中运行下列对照：

1. 预期操作通关，并保存真实输入记录，演示按原tick注入输入。
2. 逐次省略每个输入，每次均不能通关。
3. 不操作、开场同时操作，都不能通关。
4. 每次操作分别提前24 tick、延后24 tick，其余操作不变，仍可通关。

这证明当前关卡存在一条成功路线，并有必要操作和若干容差样本。它不证明唯一解、所有时机组合可用、难度合适或有趣，也不排除其他解法。单次±0.4秒采样不是连续区间或联合容差的数学证明。编辑几何、速度、状态或行为之后，旧解法提示可能失效，应重新试玩验证。

每批最多8次组合，最多5个计划输入，每轮模拟最多6000 tick；生成每120 tick检查进度，约8ms计算后协作让出浏览器线程，支持取消。同步验证供测试使用，异步验证与其共享同一执行流程。不会因要求三个候选而无限重试；不够三个时显示实际数量。

## 硬件和后续判断

开发机为Intel Core Ultra 7 155H、约32 GiB内存、集成Intel Arc。首轮基于CPU，36组种子覆盖3/4/5次操作的机制/空间配置，全部通过验证。耗时受浏览器与并行测试负载影响，界面每批显示实际时间；该结果不能外推为适合大模型训练或无限搜索。

下一步先实际挑选、修改几张候选，判断机制组合是否过于重复、输入是否可读、哪些创意仍难表达。之后扩展片段接口、更多因果依赖与空间布局，建立人工选择/修改的评测记录，再评估搜索优化或模型辅助。仅在目标、样本和可复现评分明确后考虑训练；可解性测试继续独立于生成方法。

验证命令：`node --test tests/generation.test.mjs tests/preview.test.mjs`、`node scripts/generation-check.mjs`、`npm run test:coverage`。浏览器检查在本地与离线两入口覆盖取消、种子重现、候选只读浏览、原稿保留、导入和解法演示，全程无头运行。

本轮完整验证：229项测试通过；计入内核、生成器等所选模块的行覆盖率99.71%、分支覆盖率93.69%。8套浏览器脚本通过，包含原首关通关、资源、画布、反馈、选取、吸附、连线和新生成流程。覆盖率不包含DOM界面模块，界面由浏览器测试验证。
