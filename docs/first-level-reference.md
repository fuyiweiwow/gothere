## 机制解释与不确定性

- 窗台转轴方向修正：按这段录像的画面坐标，是左端保持、右端落下；此前仅根据口述猜测的“右端固定、左端落下”不作为实现依据。编辑器应允许指定任意支点和目标角度。
- 窗台变化可用“支撑的移除行为 → 窗台的放下行为”表达；放下行为启动受约束的旋转，承托面同时变化。这是我们的通用实现方案；录像不能证明原游戏内部用了物理铰链。
- 花盆在生物附近落下后生物趴下，是直接可见的先后变化。“落物撞击触发生物失能”作为原型机制合理，但原作具体用碰撞、点击脚本还是预设动画实现，无法从录像确认。
- 本录像仅展示一条成功路线。未撑伞、未倾斜窗台、未处理生物的失败方式，花盆是否能砸中主角，以及云的消失时间，都没有得到验证。我们可自行定义一致、可编辑的失败规则，并在测试中验证。
- 原作短暂接近画面左边缘的下降，在极简关卡中安排在画布边界内；不为了复刻镜头而改掉既定的非终点边界失败规则。

## 当前能力缺口

v0.9.0 已有静态斜面、主角连续下落并落在下一层，以及原先的持有、区域触发、行为调用、延迟、接触伤害和高度运输。尚无通用物体承托、旋转支点、物体与物体的撞击事件，也没有持有物影响主角下落速度的能力。现有 `height` 只控制显示/选择，不能作为物理碰撞形状；`inactive` 也不能同时承担隐形、无碰撞和失去支撑的全部含义。

因此当前版本已能表达静态多层坡道与下落路线，但尚不能完整表达原关卡的动态结构。不能用隐藏高度通道或主角传送来伪装旋转窗台。

## 原型验收目标

使用无美术资源的几何地图和可编辑 DSL，制作一张原创短关，至少能演示：

1. 主角在多层路面连续行走，斜面上的脚底位置随 x 改变。
2. 主角离开边缘后连续下落，能够落在下方承托面；持有某物可启用缓降效果，落地后恢复行走。落地事件可连接转向行为。
3. 指定支点和目标角度的旋转动作改变物体及其真实承托面，主角能够沿完成后的坡面走到下一层；任意交换支点都可生效。
4. 临时通路可以由行为启用，并可按编辑器配置持续或恢复；外观与可承托状态分别定义。
5. 一般物体在失去承托后下落，撞击另一物体时可调用其指定行为；生物趴下/失能期间解除阻路或伤害。换成几何方块后逻辑相同。
6. 连线只定义因果，不控制重力每帧位移。一般物体的支撑丢失由模拟检测，不能要求每一对上下物件都手工接线。
7. 重置、逐帧模拟、事件日志及回放能稳定复现同一条路线；同 tick 的多个接触按确定顺序处理。

## 开发顺序

1. **斜面与下落小场景（v0.9.0 已完成）**：端点高度、支撑采样、下落和连续落地检测；双向上下坡、窄落点、相邻面接缝、重叠面和支撑消失验证。新图用可选 `world.physics` 开启，旧地图结果保持。示例、端点编辑、重力配置、回放和离线流程可用；普通物体下落仍未实现。
2. **受约束运动小场景**：通用姿态、支点、目标角度和持续 tick；事件驱动旋转，碰撞/承托面与图形同步。运动完成另有明确事件或等待语义，不能把现有 `done` 悄悄解释成所有持续运动都结束。
3. **物件互动小场景**：持有物带来的缓降效果、一般物体失去支撑后的下落、落物撞击事件和生物反应。先限制为固定朝向的简单形状，堆叠不包含旋转角动量。
4. **完整灰盒关卡**：由以上数据组合屋顶、临时通路、可倾斜结构、缓降、落物和出口。在编辑器中修改关键参数后仍可运行；JSON 导入导出与离线文件一致。

## 实现边界

先实现固定步长下的有限 2D 支撑与下落模型：斜线承托、重力、落地、简单碰撞/支撑关系和显式受控的旋转动作。行为仍由现有事件、动作、延迟与命名行为 DSL 表达。角色继续按关卡路线行走，不改成完整刚体；不追求滚动、角动量或任意物体堆叠。若例子或试玩揭示这些边界不足，再评估引入物理引擎。

场景用几何占位和文本标注；本阶段不复制原作图片、动画、音效或关卡美术。目标是验证玩家能否用我们的编辑器做出并理解这组交互。
