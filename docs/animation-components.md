# 通用动画组件的可行性与调研

日期：2026-10-29。本文保留事前设计与范围评估；下面标明 v0.16.0 已实现及后续范围。

2026-10-30补充：v0.17新增通用「浮现展开」，并用普通烟囱行为/延迟调用隐藏烟雾通路。当前为9种整体运动、16个反馈槽。未触发的通路完全隐藏；隐藏资源的独立预览不改写初始状态。

## 本轮实现状态

已交付8种整体运动、3种粒子、6种程序音效、短音频导入、独立触发槽与跨图层复制，并接入首关17槽。编辑预览、JSON、暂停/重置、死亡表现时钟与单文件离线已经过自动验证。操作见 [编辑器说明](editor-engine.md)，字段及边界见 [内容模型](content-model.md#表现反馈槽)。

当前预设是固定运动算法加参数，槽可组合和复制；尚无自定义关键帧、命名配方库、骨骼或粒子世界空间模式。下面关于未来可保存自定义配方、任意组件组合和肢体动画的部分是扩展方向，不能作为已交付功能理解。

## 完成概率的含义

目标：在现有 Web 编辑器内提供一组内置动画、简单粒子特效和音效槽；可绑定任意资源图层/对象挂点，通过行为或生命周期事件触发，可在编辑器配置、保存、重放，并接入现有首关。

事前在以下范围固定、允许迭代调试的前提下，我对完成可用原型的主观工程判断为 **85% 左右（估计范围80%～90%）**。这不是统计成功率或交付保证，也不代表商业成功概率；现在应以本轮实际结果验收：

- 保持2D、现有JSON/模拟/渲染分离的结构，按现有有限场景规模验证。
- 首版约6～8种通用运动预设、2～3种简单粒子预设，声音支持导入、试听及触发。
- 配置以属性表单和预览为主，完整关键帧时间轴暂缓。
- 不要求自动生成角色手脚动画、任意骨骼动画、真实流体或复杂粒子碰撞。

事前基础是通用对象/行为、逻辑与图片独立绑定、固定tick、图层变换和逐帧图片采样。本轮已补齐表现触发与实例生命周期、相对变换采样、粒子发射器、音频管理及编辑器配置；单元和浏览器检查覆盖这些边界，实际创作体验仍需试玩评估。

Steam正式作品还取决于内容量、预算、制作时间、画面/音频标准及发行要求，目前不足以给整个项目一个可信的完成百分比。应逐阶段以可运行交付物重新评估。

## 成熟做法与一手资料

| 方法 | 资料 | 对本项目的意义 |
| --- | --- | --- |
| 对属性进行补间，配置时长、缓动、串行/并行和循环 | [Godot Tween](https://docs.godotengine.org/en/stable/classes/class_tween.html)、[Phaser Tweens](https://docs.phaser.io/phaser/concepts/tweens) | 运动不依赖物体名字或特定贴图，可以施加在图片的显示属性上 |
| 内置冲击、回弹、抖动等参数化操作 | [DOTween 文档](https://dotween.demigiant.com/documentation.php)中的 Punch/Shake | 提供创作者直接选择的预设，参数化强度、方向、时长；参考其抽象，不把Unity库直接接入Web |
| 粒子由寿命、发射间隔/数量、速度、方向、缩放和透明度等参数形成 | [Godot 2D粒子](https://docs.godotengine.org/en/stable/tutorials/2d/particle_systems_2d.html)、[Phaser Particles](https://docs.phaser.io/phaser/concepts/gameobjects/particles) | 烟雾、尘土、火花可以使用自带基础纹理与发射配方，不必每次绘制完整帧序列 |

这些资料证明机制已有成熟实现；把它们适配到本项目DSL、暂停/回放及离线编辑的难度，仍是本项目自己的工程判断。采用这些组织方法不要求迁移引擎。

## 提供给创作者的能力

第一层是有限的显示组件：位移、绕挂点旋转、独立轴缩放、透明度，以及组合顺序、缓动和重复策略。只对渲染副本施加变换，不修改逻辑位置、承托或碰撞。

第二层是内置配方：抖动、轻跳、挤压回弹、后坐、摆动、脉冲、淡入/淡出等。组件参数采用相对显示尺寸、归一化挂点和可编辑强度，使同一预设适应不同大小图片。配方应保存为数据，创作者可组合并保存自己的预设；新增一种已有组件的组合不需要修改代码，新增底层运动算法仍需开发。

第三层是可挂到对象上的参数化发射器，内置烟雾、尘土和火花配方及简单基础纹理。位置/方向由挂点定义；设置粒子数量、寿命、速度、大小/透明度变化和颜色。随机差异由固定种子与触发标识产生；限制存活数量并在重置时清理。烟雾是否伤害仍由独立逻辑能力决定，粒子不参与物理判定。

行为表现槽组合以上配方与声音资源。例如「喷出」绑定：本体挤压回弹 + 顶部挂点喷烟 + 喷气声。同一行为与配方可应用于烟囱、阀门或其他对象，不识别它们的名字。制作者默认只需选择目标、预设和少量参数，不必寻找现成动画或写代码。

死亡先提供整体倾倒、短促抖动、闪烁和淡出组合，可应用于不同角色图片。单张扁平图片无法自动产生自然的手脚、面部或衣物运动；这些效果以后通过可选逐帧资源或分层骨骼提供，不承诺所有动画都能由通用变换生成。整体倾倒可能需要超出现有逻辑pose的角度，仍属于独立显示变换，不能放宽逻辑承托的角度约束来实现。

## 工作原则与主要风险

通用组件和数据配方符合项目的能力扩展原则。只有把某个关卡的特定烟囱写死、用播放动画代替真实搭路、或按对象ID指定预设结果，才会绕过表达能力。

真正需要验证的风险包括：多个动画操作同一属性的覆盖/叠加；显示挂点与逻辑姿态组合；重复触发、暂停、重置和视图切换的生命周期；音频不重复播放和浏览器启动限制；死亡后有限结算表现仍能推进。优先明确覆盖、叠加和取消语义，不一开始开放任意冲突混合。

## 先通过的小验收

1. 把同一挤压回弹预设施加到不同大小/贴图的图层，换目标无需改代码；配置可复制并保存为JSON。命名配方库留待后续。
2. 任意指定挂点播放烟雾，改变位置/方向/颜色/粒子数，并同步播放声音；全部由编辑器保存为JSON。
3. 同一行为反复触发，暂停/继续、重置、切视图后无重复声音、遗留粒子或显示变形。
4. 不同原因失败时完整播放通用死亡反馈并允许重试；关闭全部表现后，逻辑回放结果一致。
5. 单文件离线版本保留同样的配置、导入和播放能力。

通过这些检查后再扩大预设库。若某一步受阻，先缩减粒子数量、预设数量或编辑方式，不以增加特殊关卡脚本来掩盖问题，也不因需要少量专门角色素材就放弃整个组件方案。
