# 上班路：角色、接触叙事与首章打磨

记录：2026-11-06，基于用户整章试玩反馈。v0.37.0 已实现下述公交站小样；其余内容保留为后续计划，不表示商业品质已验收。

## 首次小样 v0.37.0

公交站与完整街区已使用同一主角候选：厚镜片、独特发型、工牌与棕色包。横走、向里、向外各八帧，共用112×96画布及(56,90)脚点；倒地有独立八帧。移动物体从自身动作首帧起步，朝向取实际位移。开场赶路动机没有在这轮加入，人物性格和最终造型仍待试玩判断。

候车队伍通过普通区域事件播放留意动作；真正碰到哪位乘客，就由该对象的 `lost.cause` 订阅播放伸臂挤开。主角播放失衡、倒地和落地尘土/音效，模拟在接触时立即停止，表现只在有限尾声前进。没有推搡位移或刚体力学，也没有由动画结束决定伤害。移除整个 scene 后，模拟结果一致。

反馈槽可编辑原因对象、图片帧、帧率、延迟、时长与结束保留；模板复制重映射对象和图片引用，TS 源码用具体 Entity/ImageAsset 引用。新增资源为原始CC0矢量，仍是原型动作。行人、汽车、电瓶车和狗的专属接触动作，以及公司街段、连线阅读负担和更多生活余波，本轮没有展开。

验证：399项自动测试通过，内核及选定反馈/编辑模块的覆盖率门槛通过；公交站、整章、反馈、模板与源码创作流程完成后台浏览器检查，包含在线/离线、两视图通关、真实接触与有限尾声、帧/原因修改及撤销、TS 往返、暂停/重置/静音和草稿保存。画面已检查实际场景截图，动作流畅度、人物辨识度与趣味仍需用户短时间试玩判断。

## 用户反馈与当前范围

整章结构基本可接受，距离商业品质的主要差距集中在角色、运动、因果交代和美术协调。用户提出的高度近视书呆子是候选，不是已确认人设。此前「动画先不深入」现在允许针对移动和失败表现做有限完善，不因此启动完整动画制作工具。

| 问题 | 下一步验证 | 完成标准 |
| --- | --- | --- |
| 主角像普通路人，持续赶路缺乏动机 | 少量造型候选与开场动作 | 实际游戏尺寸下容易从其他人中辨认；不用说明文字也能感到他执拗地赶去上班 |
| 人物移动不自然 | 公交站短片段中的步态、脚点、方向与状态切换 | 连续观察没有明显脚底漂移、身体跳位或错误朝向；分别检查横走和向里/向外走 |
| 失败只有统一倒地 | 先完整制作一次乘客推搡 | 能看清谁做了什么、何时接触、主角如何失衡；改变接触对象后反馈仍正确 |
| 缺少事件前后生活行为 | 每处先补活动前因，再选少量有意义的余波 | 等待中的角色有自己的事情；成功后不会全员无理由静止或重复抢跑 |
| 连线过密 | 先用现有相关连线筛选完成一次修改任务 | 用户能找到一条输入、一个目标行为和它的输出，无需先整理全图 |
| 公司和周边不协调 | 公司所在街段的整体构图与素材校准 | 同视角、同成人尺度、门洞和基脚合理，公司有辨识度且自然属于该街区 |
| 内容偏少 | 先验证既有对象的动作与关系密度 | 少量对象也能产生可读的冲突和结果，再判断是否需要新增机关或扩图 |

第一章的容量暂不继续扩张。序章可以解释人物和日常，但先让首章本身可读，避免靠未来序章补救当前看不懂的动作。

## 主角候选：造型与动机分别验证

可先探索「认死理的赶路职员」：厚镜片、独特发型或前倾轮廓、固定携带物，以及区别于路人的步幅。辨识点控制数量，用同一套轮廓覆盖左右、向里和向外方向。具体造型未定稿。

高度近视可以帮助形成外观，但单独不足以解释所有危险下都持续前进。动机可以通过开场整理工牌、看时间、确认公司方向后立刻赶路等无字动作表达。人物的注意力与固执共同支持「一直往前」的玩法，不要求加入新的操作控制。

先在实际显示尺寸中对比候选与场景路人，再制作整套步态；避免一边大批量画帧，一边反复改主角轮廓。

## 失败表现：共用结尾，分别交代起因

v0.36.0 基线的实现事实（以下缺口中的 cause 与单次帧播放已在 v0.37.0 补齐）：

- `src/editor/commute-chapter-scene.js` 为主角绑定统一 lost → fall / dust / thud。它可以表示失败，但没有完整的施力者动作。
- `src/core/engine.js` 的 lost 信号保留 reason，并统一以 actor 为 source；没有在该信号中保留本次施事物、接触位置和方向。此前 contact 事件虽有来源，仍需设计明确关联，不能猜测最后一条日志就是原因。
- `src/render/resources.js` 在 lost / won 状态将普通帧动画固定为首帧；`src/render/feedback.js` 已支持有限结算尾声。增加图片帧本身不能自动得到完整失败过程。
- 当前主角主要使用少量静止/迈步帧，方向变体与其他人物的移动帧也需要在实际播放中检查。运动问题是否来自帧、基准点、速度、朝向或状态切换，需分别验证，不能只提高 fps。

建议的通用表达为「参与对象 + 实际接触事实 + 表现绑定」。接触事实来自模拟；动作起势、主角受击、对方反应、短音效由可编辑表现组织，不依赖对象的显示名称。

| 遭遇 | 需交代的动作 | 可共享的部分 |
| --- | --- | --- |
| 候车队伍 | 乘客拥挤、肩或肘挤出通路，主角被推失衡 | 受击方向、失衡、倒地与落地音 |
| 闯灯行人 | 对方注意力在手机，身体实际撞到主角 | 接触反馈、双方短暂反应、主角倒地 |
| 占道汽车 | 主角前进撞到停住的车身；汽车不无故主动攻击 | 前进中断、反冲、倒地 |
| 电瓶车 | 来车路径、车身接触和骑手反应 | 受击、滑倒、接触声 |
| 狗 | 狗关注主角、靠近或扑咬，主角有对应受击动作 | 失衡与倒地，咬合部分需要合适的专用资源 |

共享的是流程与基础动作，推搡和咬合仍需要能表达相应肢体关系的部件或帧。现有整体旋转、抖动、尘土不能自动生成这些姿态。不得用关卡 ID 分支或播放一段预设影片替代普通物体、事件和资源的组合。

真实接触决定失败，表现播放不能推迟碰撞判定或让已失败的游戏继续接受输入。结算尾声若需要对方参与，也应使用可配置、只读的有限表现；重置、暂停、单步、回放、在线/离线与关闭表现后的结果须一致。具体数据字段在样例实现时再确定，本文不提前固化一套大型动画协议。

## 连线：先减少阅读范围

当前 `src/editor/ui.js` 已提供「全部连线 / 选中物体的连线 / 隐藏连线」，默认值是全部。转接点和自动布线也已存在。因此先验证已有功能的默认行为和可发现性，不重复开发一个同名筛选器。

建议依次验证：

1. 日常选择与移动物体时优先展示关联；全图总览保留明确切换。
2. 选中事件槽或行为时，只聚焦它直接相关的输入/输出，并能从列表定位目标。
3. 关联仍多时，再评估按当前街段/组合隔离、展开后续一层关系或合并平行线；不一次引入完整节点编辑器。

这些都是编辑视图状态，不能删除逻辑、改变规则执行顺序或写入运行依赖。修改一条连接后，应能立即核对来源、条件、目标行为与真实结果。

## 生活行为与余波

用户明确认可拖车离开后车主端早饭追赶。整章已经有「交警制止行人，过街后自己的手机又响」的余波，后续先检验它在整章尺度上能否被看见，再决定是否补新段落。

候车时关注来车、骑手看路或找近道、狗等待食物等，可以建立事件发生前的生活状态。每段不强求一个大反转，也不让所有演员持续大幅运动，以免干扰路线、操作线索和主角。

可评估一到两处短余波候选，例如骑手被挡后走正常车道、狗吃完后只顾找碗里的剩食。候选需有前因且不阻挡已通过的路线，不能为播放后续动画改变已确认的通行结果。尚未承诺全部加入。

## 公司与章节美术

当前公司使用独立建筑资源绑定终点，与沿街公寓的显示尺寸和建筑轮廓不同；用户已指出整体不协调。应在公司、临街建筑、门前路沿和外围背景的同一画面中校准，而非孤立替换公司图片。

先确定统一视角、成人高度、门窗比例、屋檐厚度、基脚、阴影和色板，再拆为普通图层。主角与关键动作优先拥有明确的资源规范。章节素材包继续保留背景大块和需要变化的独立部件；编辑器负责组合、绑定和复用，美术仍需设计和制作。

后续新章节可以沿用人物、规范和编辑能力，但新环境仍需专门素材。不把「可生成图片」等同于动画一致、资产可编辑或商业品质已通过验收。

## 小步交付顺序

1. 保留当前整章基线；先完成公交站中的一段正常移动和一次明确推搡失败，形成可直接试玩的比较样例。
2. 验证主角造型候选及动作资源规范，再按实际接触将表现应用到其他遭遇。
3. 同期仅修正影响本次创作的连线聚焦操作，保留完整逻辑总览。
4. 校准公司街段，检查各角色的日常活动和已有余波的可见性，再挑选少量新余波。
5. 用户以短时间整章试玩判断可读性、角色辨识度和趣味。测试继续覆盖机制、确定性、编辑保存与旧关卡兼容；不能用测试通过替代这些体验判断。
