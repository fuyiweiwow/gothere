# 公交站手绘素材试作

v0.40.1，2026-11-10。验证 SpriteCook 的统一参考图能否从静态图走到普通可编辑、可试玩的场景。当前只升级独立公交站，不覆盖整章或旧草稿。**构图修正后，用户同意暂用现有素材。人物步态及人物/背景风格搭配列为后续美术待办，暂缓动画打磨与新增生图，继续推进玩法和关卡验证。**

- 编辑：`http://localhost:4174/?sample=painted-bus-stop`
- 无提示试玩：`http://localhost:4174/?play&sample=painted-bus-stop`
- 离线试玩：`dist/gothere-painted-bus.html`，直接打开即可，无需参数或网络。
- 离线编辑：`dist/gothere-editor.html?sample=painted-bus-stop`，也可在示例列表选择「公交站 · 手绘素材试作」。
- 修正后的独立草稿槽：`commute:painted-bus:02`。旧 `:01` 的修改保留，显式打开样片链接会进入新版。

## 接入范围

41份运行时资源约1.41 MiB，包括主角静止、8帧行走、6帧倒地，3位乘客各自的静止与4帧步行，公交的旧门侧与新无门侧、旧门扇、候车亭、树、天空、地面和4段建筑。当前场景只使用无门侧车身。天空、建筑、地面和道具分离；候车亭移动后不会在背景留下另一座候车亭。所有图片、动画槽、状态变体、声音槽、绑定与层次仍是普通场景数据，可在编辑器和 TypeScript 项目中修改。

先由已有布局生成背景，再移除活动物件、裁出建筑与地面；公交、候车亭和树分别生成。所有生图使用同一主角母版约束配色、笔触和比例。主角和乘客各自动作独立生成，统一192×192画布、脚点(96,180)，每段动作只用一个缩放比例。倒地动作保留完整横向轮廓，并把落尘时机移到落地之后。

站立、行走、开门、上车、失败均不会切回旧矢量演员。乘客专属推搡尚未生成，当前只保留轻微的通用后坐反馈；主角倒地仍是原型帧，不代表商业级动画验收。此片段没有内外行走，因此未用侧向精灵冒充整章内外动画。

## 保持的边界

玩法复用原公交站：提前点击、依次上车、关门、靠近后驶离、未操作撞队伍失败、整车驶出画布。v0.40.1 将公交及驶离目标移到独立的前景车道，轮胎底线为580，人行道路缘约为520；队伍与主角仍走490的人行道。相机看见的是公交道路侧，上车门在远侧，车身遮住上车过程。去掉可见门扇、门洞和车身弹跳；门声仍是普通反馈槽。组合按行走层拆分，避免跨层逻辑组合。车身无门侧使用原图相邻窗口和下部车身补齐，保留原资源，无新增生成任务。事件和时序保持，运行内核和渲染器没有公交专用分支。旧公交站、整章、横版兼容图和旧资源ID保留。

v0.40.0 试作使用免费积分20，结束时剩余2；v0.40.1 没有新增生成消耗，未使用专用动画接口。新资源的来源和提示词见 `assets/generated/painted-bus-v1/generation.json`，测量、裁切和缩放见 `processing.json`。这些生成图与原创CC0矢量素材分开记录。

## 复现与验证

原始输出本地保存在 `output/imagegen/bus-integration-v1/`，不需要随运行页面发布。`scripts/process-painted-bus.py --source <原图目录>` 执行去品红、轮廓提取、共享缩放与建筑拆层；需要 Python、Pillow、NumPy。它只处理已有生成图，不绘制角色或补画场景。随后运行 `node scripts/pack-assets.mjs` 更新内嵌库，再构建。

`tests/painted-bus.test.mjs` 验证车道归属、全程轮胎位置、前景遮挡、不可见远侧门、玩法时序、完整退出、失败来源、资源引用与脚点、来源标识和 TypeScript 往返；`scripts/painted-bus-check.mjs` 用无窗口浏览器验证实际车轮像素位于路面、新旧草稿并存、编辑选择与保存、真实点击上车、失败动画收尾、无提示模式、独立离线文件零网络请求。画面截图在 `artifacts/painted-bus-*.png`。

人物目前偏细腻绘本插画，背景更简化，步态仍有不协调之处。用户同意先用这一版继续验证玩法，暂不要求重做。后续恢复美术打磨时，先在同一小构图中确认人物、建筑、车辆和实际尺寸，再成批生产动作；步态通过短片逐项核对脚底接地、步幅与位移、重心及摆臂。大头、同一参考图、滤镜或测试通过均不能替代画风验收。整章换图仍需另行确定范围。
