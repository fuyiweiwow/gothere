## 地面与尺度校准 v0.27.1

用户指出纵向连接不自然、骑手太大、站棚太高、斑马线太宽。检查发现，之前正面店铺、收窄的长条通道和不统一的素材尺度混用，连接容易读成桥或坡道。采用固定轻俯视角的平行插画，地面保持等宽，通过建筑浅屋顶、侧墙和路缘表达空间。逻辑仍是 v3 二维分层，三条街实际高度均为0；不增加相机、自动缩放或三维物理。

## 路线与空间分工

从近街起点向右经过公交站，在右侧斑马线向里到中街；向左经过早餐铺前的占道车辆，在左侧小巷继续向里到远街；最后向右赶到公司门外。三条街都要有实际行走与生活内容，不能以短终点平台充当第三层。两处内外连接实际高度不变，远近归属不等于升降。

| 区域 | 行走方向 | 主要内容 |
| --- | --- | --- |
| 近街 | 左到右 | 起点、公交站、候车队伍、右侧路口 |
| 右侧斑马线 | 向里 | 看手机的行人、交警、行人信号 |
| 中街 | 右到左 | 早餐铺、占道车辆、电话清障、车主追车 |
| 左侧小巷 | 向里 | 电瓶车抄近路、活动路障、明确的进出口 |
| 远街 | 左到右 | 拖放摊边早餐到狗碗，让守路的狗去吃，到公司外门结束 |

电瓶车冲突集中在小巷与路口附近，不占据完整横向街段。车辆初始在远街画外，48 tick 驶到巷口，再用 `move.passage` 进入 alley；通路上探路120 tick 后根据路障状态决定退回或抢行，同时关闭接收窗口。路障拖到巷口旁的接收点，留下主角的步行空隙。退回先真实到达通路端点，再通过 `move.plane` 沿远街离开；未处理时主角在巷内与车辆真实接触失败。没有隐藏替换车辆或传送。横向演示仍作能力回归样例。

## 连接不只连接路线

整关使用一名持续行走的主角、一个起点和一个终点。主角速度55，三条街实际高度均为0，顺序为 `front → crosswalk → middle → alley → far`，约一分钟。右侧过街与左侧窄巷分别以160和150的逻辑距离决定通行时间，独立于图片长度。`road` 和 `bus-road` 是车辆使用的辅助车道，不计作额外的主角街道。

局部事件由接近区域或行为完成启动：走近路口时手机行人入场，进入中街后路人才开始生气并允许叫拖车，走近窄巷时骑手开始探路。清障完成后车主端早餐追出店门，车与拖车均驶出整张画布。不会从整关 tick 0 同时播放，也不使用累加的绝对 tick 脚本决定结果。完整测试中的绝对时间仅用于模拟玩家输入。

本章路口没有继承旧片段的 `crosswalk.board → hurt` 规则。未处理时主角会真正走入斑马线并接触行人后失败；交警抵达、行人退回且实际走出通路后信号转绿。成功过街后两人又低头看手机，沿用已认可的余波。

先确保空间、角色行动和时间连续，再选择少量跨事件复用。活动路障应属于沿途合理的街景，与接收处保持可发现、可操作的距离。公交驶离、拖车离开和车主追车要有可读的去向；不强行规定所有事件互为开关。下一段应在前段结束前可被观察到，让玩家有预判而不是等场景切换。

## 构图与实现顺序

先安排同一街区的建筑占地、路沿、转角、两处紧凑通道和画外延伸，确认人物比例、遮挡和路线可读，再整合资源。保留统一色板及可复用物件，独立演示的大幅背景需要重新构图。三条完整演示图简单上下叠放无法满足这一目标。

先制作整关路线灰盒和构图预览，验证三条街、两处连接以及人物全程可见；随后整合既有互动与事件时机，最后补环境与叙事余波。动画维持当前水平，程序生成与新增独立片段暂缓。
