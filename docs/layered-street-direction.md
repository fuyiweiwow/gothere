# 二维分层街区：空间方向修正与内容盘点

日期：2026-11-04。依据：用户对上班路 v0.20.0-spatial.3 的试玩反馈。盘点版本：`5c8f6dd`。

本文件保留试玩后修正方向的设计依据。后续 v0.21.0 已接入二维分层首版：显式局部连接、单独的真实高度、方向动画绑定、物品放置及接收事件；精确语义与限制见 [分层 DSL 规范](layered-dsl.md)。下文统计针对修正前版本，可复核数据保存在 [内容盘点](../references/level-content-audit.json)。

## 为什么修正方向

上班路证明了移动承托、旋转和显式路线可以共同运行，却没有证明整图采用统一三轴空间适合本项目。末段升降台接近起始候车亭的屏幕位置，两条不同高度的路在画面中像是接通；透视路面、侧视车辆和原横版建筑混用，又削弱了空间提示。世界坐标正确、深度测试通过，都不能代替玩家对画面的理解。

后续采用二维构图与有限的前后分面。大部分路仍按横版方式创作；局部通路可以向画面内、外延伸，以连续行走表现前街、后街或场地不同区域之间的连接。不要求创作者把整张图建成满足统一透视的三维街区。这里描述的是我们选择的实现方向，不声称知道《梦游先生》的内部实现。

## 最小语义

1. **行走面的归属**：前街、后街、屋顶等是明确的路线/面。相邻或重叠的屏幕轮廓不自动接通。物体、感应区域和人物都归属于一个面。
2. **显式局部连接**：只有画出来并配置的巷口、过街段、楼梯、平台等可以换面。连接有入口、出口、可用条件、移动过程及到达事件；向里/向外走不能通过瞬移或特定物体名称实现。
3. **行走与升降分开**：向画面上方走可以只是进入后街，不能因此增加实际高度或触发下落。真正的上坡、升降、失去承托和落地继续使用高度及支撑语义。连接需要明确是走到另一个面，还是实际升降/运输。
4. **显示与接触分开**：前后次序、遮挡组和必要的局部遮罩服务二维画面。不同面的车辆不会因图片重叠撞到主角；同一面上的有效接触也不能靠调整图片层级消除。
5. **失去支撑有确定结果**：人物不会为了等连接而停住，也不能因为屏幕下方有一条后街便落过去。当前面的真实下层承托或显式配置的落点关系决定落地；没有落点就继续下落并失败。
6. **只有一套编辑器和行为模型**：对象、多个行为、连线、持有、动作反馈、资源绑定、历史和 JSON 继续复用。横版 v1 屋顶关保持原语义；空间 v2 草稿保留，不静默丢弃数据或强行换解释。

创作者首先看到的是「这条路属于哪个面」「在哪个入口换到另一面」「怎样移动和遮挡」。具体字段与版本迁移在实现最小验证时确定；不把现有 `scene.layer` 的图片绘制顺序当作逻辑面的归属，也不把旧 `y` 坐标整体重命名为纵深。

例如前街与后街可以在画面中一上一下、实际同高；人物在巷口沿一小段可见通路走向后街。上方的天桥另有真实高度和桥柱，不能与后街混为同一层。构图必须使通路端点和连接关系可读；“屏幕交叉不接通”本身不足以修复一张看起来接通的画。

## 美术先统一视角

先用同一套简洁的侧视轮廓、人物比例、描边和色板搭街区；向里、向外的连接单独准备少量匹配的路面和转身表现。正面建筑、侧视公交和自由斜投影道路不再任意混搭。素材使用数量不作为完成条件。

地图依次检查整体轮廓、路口与楼层连接、角色脚点，再安排店面、站台、车流、排队的人、摊位及街角小物。布景应解释街区生活与通行方向，留出可操作物轮廓与主角可见性，不靠铺重复窗户或图标填满空白。物体外观仍作为普通可编辑资源保存。

上班路实体总数更多，但命名行为更少、可点击对象更少、静态路面更多。4个点击对象中，卸货板、检修盖板和升降台均直接改变通路；信号灯主要服务公交承载。工牌只有一条自动拾取—自动刷卡链，没有选择使用对象、改变用途或与其他物品组合。

图层也不是可见物件数：屋顶关的34个星星、37个檐线、18个夜窗和18个百叶窗已经占107个图层。两关的不同基础贴图数接近。因此90对160可以说明制作规模，不能单独解释场景为什么空、为什么不统一，更不能当作趣味评分。

### 一个额外的因果检查

固定上班路的既定输入计划，逐个关闭私家车、追车上班族、看手机行人的移动行为，或逐个关闭两辆电瓶车的巡逻与伤害，其余关卡保持原样。五次实验都仍在 tick 3042 通关，与基准相同。

这说明这些对象在**这条已测解法**中没有改变通关结果或完成时刻，不能把它们都算成五种已完成的谜题。它不证明这些对象在所有输入和失败路线中都没有作用；也不要求所有布景都成为必解障碍。叙事性活动本身可以保留，但应与实际参与因果的互动分别统计。

### 为什么还没有原作平均值

`references/snoozleberg/study.json` 目前是施工、碰碰车、鬼屋三组片段的证据档案；没有覆盖每关完整物体清单、全部点击对象或所有状态，格式也不是可运行关卡。不能把观察条数当物体数，不能把这三段当三张已完整统计的关卡。

后续按完整关卡分别标注：可识别的场景物件组、可操作对象、自动活动对象、关键因果链、物品参与的因果链、同一对象的多用途和空间复用；记录证据、已确认/未知及统计口径，再对口径相同且完整的样本报告均值和范围。现有两份项目样本的均值只作为自身版本对照，不设为目标配额。

## 下一张上班路要检验的内容

优先顺序：先清楚表达街区和局部内外通路，再做物品与角色的关系，最后补充有主题作用的布景。暂缓程序生成和新一批独立地形机关。

先做一个局部样例，同时具有前街/后街换面、真正的高处路面及画面交叉，确认区别足够清楚，再铺满整图。新连接必须能在编辑器配置、保存、运行和重放；旧屋顶关继续回归。

物品题先做一条短而可读的因果链。例如把早餐用于吸引挡路动物，再让动物移动影响另一对象；或者使同一物品在携带、交给别人、放下后产生不同用途。这些是待验证的内容构想，不是现有引擎已支持的功能承诺。首先尝试用现有的持有、状态条件、行为和接触表达，缺少给予、消耗、目标选择等关系时再补成通用能力，不能按“早餐”“工牌”的名称写判断。

创作盘点至少分开记录：可辨识场景物件、可操作对象、自动活动、纯布景；关键因果链、物品/生物交互链、对象复用及可选反应。下轮先验证一条真正改变结果的物品/生物交互链、一处对象复用和一处有趣的可选反应，再决定是否扩展数量。密度不只靠数量，还靠关系可发现、同一区域可复用以及无字的日常荒诞。

验收先看新玩家能否指出哪些路连通、人物正在做什么、物品为何影响另一对象，再看完整路线能否通过。通关测试和统计只能提供证据，不能代替试玩判断。
