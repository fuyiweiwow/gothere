# 公交站：先验证一个有因果关系的片段

v0.22.0，2026-11-04。入口 `?sample=bus-stop`，约17秒。当前是单个事件片段，用于检验构图、无字叙事和编辑流程；三街区原型保留在 `?sample=commute`，尚未按本次方案重做。

## 本轮为什么收缩范围

三段道路能够通关，仍然存在角色反复出现、操作缺少理由、建筑与道路脱节的问题。路线正确、缺步骤失败、自动测试通过只说明机制可执行，不能说明关卡有趣。本轮不增加机关数量或生成器，先把一个街口的因果和视觉做完整。

玩家点击公交，车门打开；队首走到入口后真正完成移动，再轮到下一位，直到队尾上车、队伍消失。最后一位进入后才关门。主角接近车门时司机摆手，公交驶向画外，主角继续步行。不操作或太晚操作，主角撞进排队的人群，失败。提前开门允许成功，没有为了时机难度强行让乘客重回队伍。

顺序使用普通 `invoke`、`move`、`moved`、`set`、`after`、区域 `enter` 和条件。队伍不是一张不参与玩法的布景。乘客完成到达车门后才隐藏；没有用固定延迟猜上车结束时间。门扇、司机摆手、车身、乘客是独立图片，状态和移动决定表现；引擎不识别公交、乘客名称。

## 连续环境与可动部分分开创作

统一采用侧视街景、局部侧墙与候车亭透视，固定的道路基线、人物比例、左上照明与灰绿/米黄/赭色板。远城用淡色，近景用更深轮廓。整条人行道、路缘、车道连续延伸到画外；店铺、公寓、办公楼有不同轮廓、开间和入口，避免三排相同房子的拼贴感。

环境仍使用普通 `scene.nodes` 与素材库：

- 大块的连续底景：晨雾/远城、连续铺面。
- 可替换的建筑组块：转角店铺、老公寓、街角楼体和画外延伸。
- 单独调整的场景部件：树池、候车亭、前景路灯。
- 活动部分：车身、门、司机、乘客、主角。

共19项项目原创 CC0 SVG 素材，约17个图层；原始矢量在 `assets/original/commute/stop*.svg`，可在矢量编辑器中继续修改。`scripts/draw-bus-stop.mjs` 保存统一色板和素材源绘制方法，运行后用 `node scripts/pack-assets.mjs` 打包。它是离线美术制作脚本，不是运行时按关卡名绘制场景的代码，也不代表已实现面向用户的建筑生成器。

建筑内部的窗户、檐线等细节属于该素材；本轮仍在外部矢量工具中修改。编辑器可以移动、缩放、替换整栋建筑，也可以另加普通图层。没有引入自由绘画或矢量路径编辑器。

## 共用编辑器的补充

图片可填 `group`（1～30字）用于组织环境、建筑、街道、布景、公交、乘客、角色等。图层列表可以按组筛选、整组隐藏或锁定；隐藏和锁定只影响编辑状态，不写入关卡、不改变运行结果。它是组织分组，尚不包含父子变换、整体移动或可实例化预制件。

普通物体图片新增可选 `variants.moving`。实际存在 `translation` 且处于 active 时，移动覆盖叠加在 active 状态图片上；移动结束恢复状态图片。可覆盖图片/帧序列，缺省字段继承状态与基础资源；显式编辑预览优先。inactive 的隐藏不被移动动画覆盖。关闭动画只冻结显示，移动和事件照常运行。

运行时在资源视图按实体实际绑定图片范围点击；逻辑视图按逻辑轮廓点击。这样大公交不会只有一小块碰撞轮廓能点。图片尺寸仍不改变接触伤害。

## 试玩验收

1. 不读提示，能否发现队伍阻路、公交是可操作对象？
2. 开门、排队移动、进入门、关门是否连续且容易看懂？
3. 司机的拒绝是否发生在主角接近时，能否读出“别人上了车，自己仍要赶路”？
4. 是否能把整个场景看作同一条街，而不是独立贴纸？
5. 切换逻辑、资源、绑定校准，能否理解每个活动对象与图层的关系？

自动测试检查事件顺序、早/晚操作、失败、回放、图层与逻辑隔离、动画暂停、分组操作、实际车身点击范围、JSON/撤销、旧稿保留和离线无网络。趣味性、讽刺力度和画面协调仍需要用户试玩判断。

后续在这个片段得到确认后，再用相同流程重做狗、交警、电瓶车和拖车事件。路障运行时拖放、合法接收区和无效返回尚未实现；本轮未把它们混入公交站。
