## 通用拖放

物体增加 `draggable: {enabled, targets}`；接收对象增加 `dropTarget: {enabled, radius}`。属性面板可以启用能力、选择多个接收点、修改接收半径；`enable` 动作可以改变两种能力的启用状态。放置成功产生 `placed`（`other` 为接收对象 ID），错误放置产生 `droprejected`，均可从事件槽连线。

接收半径以画布坐标为单位（12～96），与贴图尺寸、缩放和点击位置无关。拖动保存鼠标与逻辑基准点的偏移，松开时用基准点匹配允许的接收点；多个匹配按距离、ID稳定排序。接收点明确指定目标层，成功后转为接收点的位置与层归属。图片继续通过绑定跟随实体。

手势中只预览拖动位置；真正放置在下一个固定模拟 tick 执行并再次检查能力。放错时保持拖动前的实际位置；Esc、失去指针捕获、窗口失焦、暂停、重置或退出试玩都会取消手势。暂停时不接受新的拖放；旧点击在暂停时可排队的语义保留。拖放不会写回编辑草稿或增加编辑历史。

模拟 API 为 `placeAt(source, {x,y})`，并记录 `{tick,type:"place",source,point}`。沿用回放 schemaVersion 1 的可选输入类型扩展，旧点击 `{tick,source}` 原样兼容。支持该能力需使用 v0.26.0 及以上；旧回放器不理解新输入类型。`hold/place` 仍指主角持有、在附近放下，和玩家鼠标拖放分别配置，共享 `placed` 事件。

首版支持静态普通物体及明确接收点，不含自由抛掷、拖动刚体、沿途碰撞、从贴图自动推断接收区。拖放暂不与巡逻、动态刚体、旋转、承托、矩形碰撞体和通路归属组合；物体被主角持有或受控移动期间不能拖。关卡使用状态和接收开关表达“来不及”，不用关卡 ID 特判。路障到位后锁定；车辆已经决定抢行后关闭接收点，迟到的放置会归位。

## 验证与下一步

核心测试覆盖成功、真实碰撞、错误/晚放、重复输入、禁用接收点、暂停/重置、旧版横版与指定跨层接收、删除引用、模板重映射、确定性回放及美术独立。浏览器在线/离线验证实际鼠标拖放、局部缩放、两种视图、Esc归位、重置、属性/历史、JSON和旧草稿保留。

本轮322项核心测试通过，覆盖检查的总行覆盖率99.66%；新增9项放置测试。电瓶车、斑马线、拖车、公交站、模板与分层示例均完成在线和离线浏览器检查。构建生成单文件 HTML，开发过程未打开可见浏览器窗口。

公交站、清障、斑马线和本片段继续分别试玩。下一步优先将已验证的物品与角色因果组合进连续街区，检查前后事件节奏和视觉衔接；不增加孤立按钮机关或继续扩建模板系统。完整三街区章节仍未完成，趣味性须由试玩判断。
