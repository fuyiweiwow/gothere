# 神仙驿站 · 第一篓蟠桃

2026-11-02，v0.22.0-experimental，分支 `codex/procedural-generation`。

## 题材与人物

王母寿宴将近，蟠桃驿奉命将桃送给住在各处的神仙。小驿卒有点缺心眼，认准目的地就往前走；腾云法术学得不扎实，不能长时间维持。玩家帮助他利用环境走完送桃路线。山上、海底和云间都可成为未来地图，但本轮只做一位山居收件人。

这是用户提出的题材与本项目的原创故事试验。借用王母、蟠桃、仙居、祥云等意象；匿名仙长、签收笑话、茶气运输与短时法术为本作设定。

希望先验证的气质：山水清雅，人物认真，事情发展有一点荒诞。笑点通过姿态、时机、状态和结果呈现，不依赖长篇对白。神仙有自己的生活，路线穿过这些日常；既要让人意外，又要有能够理解的规律。

## 本轮小样《仙长，请收桃》

| 阶段 | 画面与动作 | 可编辑表达 |
| --- | --- | --- |
| 出发 | 小驿卒从蟠桃驿出门，背好桃篓，一直向右走 | contact → hold，手持物随人物移动 |
| 借道 | 仙长的扇子歪在两山之间，放下后恰好接通崖口 | pose + rotate + surface；人物真实踩过扇面 |
| 法术不到家 | 离开高处前启用桃篓上的腾云符，只够缓降一小段 | 持有且active时 carriedPhysics 改变重力/落速，210tick后恢复 |
| 托云上山 | 落到下层，走上茶气托起的云台，到顶后折返 | lift 的 board → 上升，实际移动载人，出口 direction=-1 |
| 交桃 | 接近交接处时放下桃篓、收起「请递桃」小帘 | zone.enter + holding 条件 → receive → drop + gate.open |
| 收尾 | 仙长仍闭着眼，手却伸出来盖章；回执浮现 | 状态图片替换、通用反馈槽，显示「蟠桃已签收，仙长本人还没醒」 |

参考路线约18.5秒，含两次玩家输入；没有为了凑点击数添加独立障碍。当前魔法是**缓降**，不能向上自由飞行；上山由显式云台完成。桃篓实际由hold/drop处理，门前交接需持有指定物体，不能靠预设胜利或识别关卡ID跳过。

云台图层跟随实际carY；本轮同时修正了通用资源绑定对升降台位置的读取，适用于任意绑定在lift上的图片。

## 如何试玩和编辑

使用本分支的本地编辑器或 `dist/gothere-editor.html`，点击「关卡实验」，选择《仙长，请收桃》，点击「导入并试玩」，再点击「运行」。提示与解法演示默认折叠；场景中的扇子、背着的桃篓可以点击，右侧同名按钮也能操作。v0.23目录默认选中后续的 [上班路试作](commute.md)，本关仍完整保留。

不会替换默认里程碑或旧草稿。导入创建副本，支持暂停、单步、重置、逻辑/资源/绑定校准切换、历史和JSON。场景预览切换时防止较早的图片加载回画到另一张图。

当前49个可编辑图层与10个反馈槽，使用18张项目原创SVG概念素材。山石、飞檐、松树、桃树、角色、桃篓、扇子、仙长和回执都是独立资源；不是整张背景图，也没有把场景写死在渲染器。素材并入资源仓库，可搭其他场景，遵循 [项目原创素材CC0许可](../assets/LICENSE-original.txt)。这只是风格小样，不代表最终绘制、角色动画或美术质量。

## 试玩后讨论

先观察：是否喜欢这个世界；小驿卒是否让人记得住；茶气、扇子和仙长的反应是否合理而有趣；是否只有换题材的感觉。若主题成立，再重做更强的情景依赖与反转，而不是直接批量生成同类路径。

海底收件人、限时主动飞行、更多神仙的独特习惯、成套关卡及主题驱动生成均未实现。先完成一次主题体验的反馈，不以更多机关或神话名词代替内容设计。
