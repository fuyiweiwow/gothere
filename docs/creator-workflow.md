# 从能编辑样例到能独立创作

更新：2026-11-05。v0.23.0 完成首个模板操作闭环；v0.28.1 根据跨章节创作反馈补充边界，后续设计与限制如下。

## 跨章节复用的边界

街道与公司内部需要不同的环境美术。模板可以复用同一主题内的建筑和陈设；跨主题主要复用角色、比例、色板与描边约定、挂点/遮挡规范，以及已有的行为组合。不能因为已有街道素材，就假定办公室章节的美术成本已经解决。

各章先确定完整构图、角色活动区域和视角，再制作环境大块与可交互部件。办公室要补墙面、门禁、工位等专门内容；既有移动、伤害、接触、拖放、时机和连线机制可以沿用。目标是让新增素材经过同一流程即可使用，而不是令一套图片覆盖所有题材。

当前 JSON 窗口是展开数据的精细编辑入口。项目中的关卡本就由 JavaScript 工厂生成；后续可提供作者用的脚本编排 API，用函数、循环与语义化操作生成同一 DSL，减少手工维护大数组。此入口尚未开发，不会把普通脚本回调自动转为可视化连线，也不承诺可视化修改能无损还原任意 JavaScript 源码。

脚本编排首版宜按「JS 生成 → 校验 → 导入编辑器微调」单向流程验证，保留脚本原文和展开结果。画布修改保存为普通 DSL；再次生成应预览差异或产生独立草稿，避免覆盖手工微调。运行与回放只依赖展开结果，使用者不用靠脚本定时器维持游戏；运行时自定义脚本是另一项能力，不在本轮实现。

## 当前已完成的小步

完整街景背景、两种整栋建筑、公交与候车队伍共4种内置模板；提供单独练习草稿。模板以普通图层、物体、行为、规则和反馈槽展开，生成独立 ID；动画帧、状态变体及音效订阅随实例保留。实例可整体移动、复制、删除和展开编辑，解除组合不改变玩法。背景保留大块结构，可分别移动建筑或继续添加环境动画；不要求逐扇放窗。活动组合按行走层落地并水平移动，离场目标可显式固定在地图坐标。

目前只提供内置模板和场景内复制；没有外部模板文件导入、自定义模板库、参数建筑生成或任意组合选择工具。后续以实际试玩反馈决定下一小步，不同时展开整个路线。

## 缺口

用户认可公交站的场景整体性，但没有美术能力时，原有贴图放置功能不足以制作类似场景。建筑内部的窗户、檐线、侧墙和色板仍由外部矢量脚本制作；编辑器操作整栋资源。可编辑成品不等于创作者能从空白搭出成品，模板闭环只解决其中一部分。

工具应让创作者用统一素材与规则表达自己的布局。无需先建设完整绘画软件，也不假设能在没有任何素材输入时自动获得好美术。需要新风格时，仍需新的素材包或美术制作。

## 建议顺序

1. **主题套件与起始场景**：先把当前素材整理成一致的街道套件；清楚区分连续环境、建筑、路面、装饰和互动对象。空白创作可以选择街景起始场景，得到统一基线、比例和色板。套件包含若干可替换的整栋建筑，而不是要求用户逐扇放窗。
2. **可复用场景组合**：一组资源可整体移动、复制、保存和再次放置，保留相对位置。组合可以只包含布景，也可以包含普通物体、图层、行为和内部连线；实例化时重新映射 ID 与内部引用。外部触发/行为明确暴露端口；结果仍由同一 DSL 与模拟执行，不在引擎中定义公交站专用类型。
3. **对接与少量参数**：资源声明路沿基线、建筑落地线、路口连接点，拖动时按这些含义对齐。先支持有限的颜色/样式替换和已有建筑变体；确有需要时再做楼层、开间数量等参数化建筑，避免首轮同时开发无限制建筑生成器。
4. **事件配方**：把已验证的“依次进入接收点”“区域触发一次移动”等普通行为组合做成可调整配方，便于更换角色、目标和数量。配方能够展开检查和修改，不把可复用误解为不可编辑的黑盒。

group 只用于组织、筛选、隐藏和锁定；v0.23.0 的 compositions 才是共同操作成员关系。路线吸附也不是完整的资源语义对接，两者需要明确区分。

## 素材模板按规则拆解：可行性评估

用户提出让模板美术素材按照规则拆解，以便使用编辑器的不同能力。此方向与主题套件、场景组合一致；v0.23.0 先以现有资源和内置清单实现，不扩展为通用美术导入器。

**保留部件并提供清单的素材模板，可行性高，开发难度中等。** 素材在制作时按用途保留独立图片或图层，附带部件位置、基准点、旋转中心、遮挡顺序和可选状态/动画等数据。导入时转换为普通资源图层，按用户选择创建或绑定现有逻辑对象；可选行为配方展开为当前 DSL。最终仍能逐件编辑，没有以公交、窗户等名称触发的引擎分支。

例如公交模板包含车身、门扇、可选轮子及车门入口标记：整体移动带动各部件；门扇可单独开关；入口标记用于摆放接收点；碰撞范围由模板显式给出并允许修改，不能直接用车身图片边界代替。只有美术部件时不自动添加拒载、伤害或乘客排队等逻辑。

首轮采用现有内置 SVG 与结构化模板数据，复用当前图层、绑定、状态变体、帧动画和反馈槽。图集裁帧、PSD/Aseprite 源文件读取和父子变换层级仍需新开发；不把当前 group 当作已具备这些能力。后续外部包格式单独验证，避免同时支持多个绘画工具源文件。

通用的位移、旋转、显隐、抖动等表现可复用；开门、肢体动作等需要合适的部件、旋转中心或专用帧。被前景遮住的内容须在素材制作时补全，避免移动部件后露出空洞。无需把每扇装饰窗都拆成对象，只拆需要独立操作、替换或动画的部分，保留大块连续布景的整体感。

**从任意扁平插画自动推断所有部件、补全遮挡并生成可靠玩法，难度高且结果难以保证，暂不纳入。** 若以后采用生成图，仍需制作或人工确认分层与标记。可选智能工具不能成为模板导入和离线创作的前提。

成熟做法参考：

- [Aseprite Slices](https://www.aseprite.org/docs/slices/) 支持命名区域、用户数据、基准点和切片导出；这些是素材描述信息，不会自动产生游戏行为。
- [Tiled Using Templates](https://doc.mapeditor.org/en/stable/manual/using-templates/) 支持保存和重复放置对象模板、属性继承及实例覆盖；可参考其模板与实例的关系，组合和内部连线仍需结合本项目设计。

现有公交模板已验证放置、拆开编辑、改变门的图片偏移、组合移动与完整通关；背景、两种建筑作为同套资源提供。没有新增轮子独立部件或特殊肢体动画。下一步先收集实际操作阻点，再决定是否增加标记编辑或自定义模板保存。

## 第一个验收任务

只使用编辑器与提供的套件，把公交站重排成另一个街口：替换建筑、调整站台与公交位置，增减乘客，重新摆放入口并连接流程。离场路径允许画外；修改后能运行、保存、撤销和导出。

验收时不编辑 JSON、不改代码、不另画素材。场景保持一致的比例和路面关系，乘客仍走到实际车门后才结束动作。若仍需开发者手工改坐标或外部画图才能完成，就记录具体阻点继续修复。

先围绕这一个任务打通流程，之后再考虑其他主题、更多事件及组合生成。关卡数量和图层数量不作为本轮成功指标。
