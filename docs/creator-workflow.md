# 从能编辑样例到能独立创作

2026-11-04，下一阶段建议，尚未实现。

## 缺口

用户认可公交站的场景整体性，但没有美术能力时，现有贴图放置功能不足以制作类似场景。此次建筑内部的窗户、檐线、侧墙和色板由外部矢量脚本制作，编辑器只操作整栋资源。可编辑成品不等于创作者能从空白搭出成品。

工具应让创作者用统一素材与规则表达自己的布局。无需先建设完整绘画软件，也不假设能在没有任何素材输入时自动获得好美术。需要新风格时，仍需新的素材包或美术制作。

## 建议顺序

1. **主题套件与起始场景**：先把当前素材整理成一致的街道套件；清楚区分连续环境、建筑、路面、装饰和互动对象。空白创作可以选择街景起始场景，得到统一基线、比例和色板。套件包含若干可替换的整栋建筑，而不是要求用户逐扇放窗。
2. **可复用场景组合**：一组资源可整体移动、复制、保存和再次放置，保留相对位置。组合可以只包含布景，也可以包含普通物体、图层、行为和内部连线；实例化时重新映射 ID 与内部引用。外部触发/行为明确暴露端口；结果仍由同一 DSL 与模拟执行，不在引擎中定义公交站专用类型。
3. **对接与少量参数**：资源声明路沿基线、建筑落地线、路口连接点，拖动时按这些含义对齐。先支持有限的颜色/样式替换和已有建筑变体；确有需要时再做楼层、开间数量等参数化建筑，避免首轮同时开发无限制建筑生成器。
4. **事件配方**：把已验证的“依次进入接收点”“区域触发一次移动”等普通行为组合做成可调整配方，便于更换角色、目标和数量。配方能够展开检查和修改，不把可复用误解为不可编辑的黑盒。

当前 group 只用于组织、筛选、隐藏和锁定；不是上述可复用组合。路线吸附也不是资源语义对接，两者需要明确区分。

## 第一个验收任务

只使用编辑器与提供的套件，把公交站重排成另一个街口：替换建筑、调整站台与公交位置，增减乘客，重新摆放入口并连接流程。离场路径允许画外；修改后能运行、保存、撤销和导出。

验收时不编辑 JSON、不改代码、不另画素材。场景保持一致的比例和路面关系，乘客仍走到实际车门后才结束动作。若仍需开发者手工改坐标或外部画图才能完成，就记录具体阻点继续修复。

先围绕这一个任务打通流程，之后再考虑其他主题、更多事件及组合生成。关卡数量和图层数量不作为本轮成功指标。
