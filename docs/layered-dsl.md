# 二维分层与内外移动规范

版本：0.21.1 / DSL v3。本文描述已经接入编辑器和模拟的能力；旧 v3 草稿仍按原语义运行。

## 三个独立概念

| 含义 | 数据 | 对游戏的影响 |
| --- | --- | --- |
| 物体属于哪条街、哪个行走层 | `space.plane` | 支撑、接触、拾取及目标判断只在同层发生 |
| 真正离开地面多高 | `space.height` | 上坡、旋转承托、升降、失去支撑与下落 |
| 行走层放在画面哪里、画在谁前面 | `planes[].depth`、`order` | 二维构图和遮挡；不冒充真实高度 |

不把内外行走统一解释成高度变化。它们共用对象、行为、事件、编辑历史和动画系统，但保留各自语义。原横版 v1 和三轴实验 v2 继续按原含义读取，不能把旧坐标静默重新解释成行走层。

为复用已有坐标和资源绑定，v3 暂保留 `spatial`、`depth` 字段名。固定 `depthX:0, depthY:-1`；普通物体及节点的 depth 必须等于所属层的 depth，编辑器自动维护。使用者在面板中操作「行走层」「画面路面 Y」「实际高度」，不必逐物体输入 depth。

画面脚点为 `screenX=x`、`screenY=originY-depth-height`。例如后街在画面上方，但 height 仍可为 0。两条街只在同一张画上相邻，不会因此接通，也不会互相承接掉落。

## 连接是一项物体能力

以下省略其他必填关卡字段，展示一个局部连接：

```json
{
  "schemaVersion": 3,
  "spatial": {
    "mode": "layered",
    "projection": {"originY": 620, "depthX": 0, "depthY": -1},
    "planes": [
      {"id": "front", "label": "前街", "depth": 30, "order": 1},
      {"id": "back", "label": "后街", "depth": 220, "order": 0}
    ],
    "start": "entry",
    "nodes": [
      {"id": "entry", "x": 420, "plane": "front", "depth": 30, "height": 0, "next": "exit", "via": "alley"},
      {"id": "exit", "x": 500, "plane": "back", "depth": 220, "height": 0}
    ]
  },
  "entities": [{
    "id": "alley", "kind": "object", "label": "巷口", "state": "active",
    "x": 420, "width": 24, "height": 12,
    "space": {"plane": "front", "depth": 30, "height": 0, "depthSize": 20},
    "passage": {"from": "entry", "to": "exit", "distance": 200, "enabled": true}
  }]
}
```

规则如下：

- 首版连接为单向直线，两端属于不同层，实际高度相同；允许纯向里、向外或带左右位移。返回需要明确配置另一组入口、出口。
- 人物必须在入口得到真实支撑，且物体 active、passage.enabled 为 true 才能进入。条件不满足就沿原方向继续走，不等候、不瞬移。
- 按 `distance / 人物行走速度` 确定通行时间，连续插值入口到出口，保持真实高度。distance 是明确的逻辑通行距离，创建时写入，此后仅重新摆放行走层不改变它；美术构图不会悄悄改变操作时机。连接拥有这段通行，只接触属于该通路的对象，不与无关行走层的物体发生接触。
- 进入、离开产生 `board`、`arrive` 事件，可以连线触发行为、动画反馈和声音。
- `enable` 动作的 `capability:"passage"` 控制是否允许新进入。已进入者完成当前通行；关闭不会把人物弹回入口。
- 出口必须连接作者铺设的路面。没有支撑会在出口继续下落，连接不会补出隐藏平台。
- 同层上坡用路面的 height/heightEnd，升降用移动承托；不绕道借内外连接假装升降。

编辑时选中入口节点，选择异层的下一节点，会创建普通连接物体。选中它可检查入口出口、切换启用、添加行为和事件连线。连接不能同时当巡逻物体、旋转板或承托面。

图片可绑定这个物体并开启 `fitPassage:true`。图片按入口出口自动设置长度、角度，厚度和偏移仍由美术编辑决定；资源本身不决定能否通行。

v0.21.1 新增可选 `passageView:{"endScale":0.65}`。图片沿连接绘制成入口宽、出口窄的梯形，`height` 是入口宽度；endScale 是出口与入口宽度之比（0.2～2），向外的连接可以配置为大于1。画面上可垂直向内、斜向内，不改变实际高度。旧草稿未配置时仍为普通矩形铺面。透视铺面统一绘制在地面层，不盖住通行人物；属性中编辑宽度、比例、偏移，长度和角度由节点决定。

## 通路上的物体与生物

普通 object 可以属于行走层，也可以属于某条内外通路。后者使用以下位置，替代 space.plane：

```json
{"space":{"passage":"alley","progress":0.55,"length":32,"depth":140,"height":0}}
```

`progress` 为入口到出口的0～1进度，`length` 为沿通路占用的逻辑长度（8～160），`height` 保留真实高度。通路物体的 x、depth 是位置缓存，运行及编辑时由入口、出口和进度推导。它可以有接触效果、行为、事件、独立图层与动画；位置不是通过贴图猜出来的。

移动仍使用普通动作：`{"type":"move","target":"visitor","progress":1,"ticks":84}`。事件仍用 contact、moved、done 等既有槽。移动者与主角以相对进度做连续碰撞检测，不因画面重新布局而改变接触时机；无关的街面或其他通路不产生接触。当前不与巡逻、旋转承托、碰撞承托、持有组合；删除仍有物体引用的通路会要求先移走或删除这些物体。

v0.22.1 中，行走层普通物体的坐标 move 目标 X 支持 -1200～2400减物体宽度，用于连续移出画面或返回。初始物体坐标仍需在地图内，主角触边仍然失败；带姿态的物体继续接受姿态端点边界校验。画外移动不会自动隐藏、销毁或复位对象，moved 仍在真正到达时发出。

v0.25.0 新增可选出口衔接。例如物体沿 alley 到达出口进度1后，执行 `{"type":"move","target":"visitor","plane":"back","x":650,"depth":220,"height":0,"ticks":90}`，从该出口的原位置开始沿 back 层继续走。必须实际处于进度0或1、目标 plane 匹配当前端点且真实高度等于端点，才转为行走层归属并开始新位移；不会从通路中段转层或跳到另一端。depth 必须等于目标层的 depth，目标坐标与 progress 不混用。行走层普通物体不能借 plane 切到无关层；此前通路进度动作仍按原语义执行。

未到指定端点、端点不匹配或已经离开通路后再次执行旧进度指令，会产生普通 `moveblocked` 事件并保留当前位置及正在执行的位移。规则和反馈可绑定该事件；moved 仅代表真实到达，done 仍是命令/延迟执行完成。首版只支持离开通路后在同一层继续移动，不包含从任意行走层重新进入通路、连续自动寻路或多段路线。旧编辑器不理解此扩展，须使用 v0.25.0 或更新版。

编辑器选中普通物体，在「位置归属」选择通路后可拖动进度，设置占用长度，并在动作中编辑目标进度。闯灯行人、电瓶车只是这个能力的普通配置；恢复、抢行、伤害、让路通过既有状态、after、move 和行为连线组合。

通路物体的 move 动作提供「移动范围」：沿通路移动，或到端点后走入指定行走层。后者显示 X、真实高度与时长；先用独立进度动作到达对应端点，再从 moved 连线调用它。编辑层基线会同步出口动作的 depth；切换物体初始位置归属时，目标按现有规则重置，可用撤销恢复。

连接物体图片可配置 `passage-enabled`、`passage-disabled` 变体，显示门开、门关等外观。未配置时沿用原 active/inactive 变体或基础图片；这些变体读取真实连接能力，不替代 enable 动作。

## 动画与动作如何关联

统一的是动画绑定方式，不是坐标：所有图片仍使用相同逐帧动画、状态变体、通用反馈和音效槽。

人物的动画状态由模拟快照推导：`walk-left`、`walk-right`、`inward`、`outward`、`falling`、`climbing`、`riding`、`lost`、`won`。向里向外取自连接入口到出口的方向，不由图片朝向猜测。普通行走可用 `walking` 变体作方向缺省；缺少特定方向时继续用基础资源。

```json
{
  "bind": {"type": "actor"},
  "asset": "commuteWorkerWalk1",
  "animation": {"frames": ["commuteWorkerWalk1", "commuteWorkerWalk2"], "fps": 8},
  "variants": {
    "inward": {"asset": "streetWalkIn1", "animation": {"frames": ["streetWalkIn1", "streetWalkIn2"], "fps": 8}},
    "outward": {"asset": "streetWalkOut1", "animation": {"frames": ["streetWalkOut1", "streetWalkOut2"], "fps": 8}}
  }
}
```

资源面板选中绑定主角的图片，在「人物动作动画」中选择方向后配置图片及帧序列。关动画只冻结显示，不冻结通行。行走帧按模拟时钟循环；暂停时冻结。首版没有脚步锁相、转身混合或根运动，路径速度不由动画帧数驱动。

## 持有物与接收对象

新增 `place` 动作：`{"type":"place","target":"breakfast","at":"bowl","range":105}`。必须真正持有 target、与接收对象同层、在指定范围内且不处于跨层通行，才会放下。随后在物品上产生 `placed` 事件，`other` 指向实际接收对象。

所以相同的早餐袋可以先放在狗碗旁触发生物行为，取回后交给门口的人。接收方的名字不进入引擎判断。条件、消耗、开门或移动全部由普通规则组合。

v0.26 另增加玩家鼠标拖放：物品的 `draggable.targets` 显式列出带 `dropTarget` 的接收对象。松开后吸附到接收对象的 x、depth、height、plane；错误放置保留原位置并产生 `droprejected`。接收对象决定所属层，不从画面重叠或图片推测层归属。`placed` 同样携带接收对象 ID，可沿用规则连线。它和主角持有的 `place` 动作分别配置；完整约束见 [内容模型](content-model.md#玩家拖放物品)。

## 当前范围

v0.23.0 的 `scene.compositions` 是编辑辅助数据，每组保存 `id`、`label`、基准 `origin:{x,y}`、资源成员 `nodes:[id]` 和物体成员 `entities:[id]`，最多64组，每个成员只属于一组。逻辑成员须处于同一行走层；组合没有运行时变换，编辑器将操作写回普通物体、move 目标和资源图层。因此解除组合不改变模拟和画面。模板放置/复制会重新映射物体、内部规则、图片绑定和反馈引用；外部引用尚不能封装为模板端口。

move 动作的可选 `editor:{waypoints:[],keepWorldX:true}` 让目标 X 在组合平移时保持地图坐标。默认目标随成员平移；此标记只影响创作操作，不改变模拟执行。帧动画、状态变体与反馈音效仍使用原有 scene 字段，不从动画结束回调驱动逻辑。

当前支持最多8个行走层、单向直线连接、同层接触和下落、通路物体及其移动/接触、局部连接动画、普通物品交互。暂不支持连接中途分支路口、曲线路径、跨层掉落映射、自动双向寻路、骨骼动画或动画根运动。需要这些能力时扩展数据定义，不按具体关卡加例外。
