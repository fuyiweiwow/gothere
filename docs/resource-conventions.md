# 作者项目的目录资源约定

状态：2026-11-06 · v0.35.0 已接入图片与声音。这里的目录属于浏览器中的作者项目，不是应用仓库自身的 assets 目录。

## 目的

将重复的资源声明、模块导入和目录索引交给编辑器维护。作者主要编写摆放、对象关系和行为；继续获得具体类型、补全、错误定位和定义跳转。目录约定用于扩展通用项目能力，不识别公交或某一关卡的名称。

## 默认规则

| 目录 | 自动处理 | 作者仍需表达的内容 |
| --- | --- | --- |
| `assets/images/**` | 识别受支持的图片，建立目录索引及类型化图片引用 | 图片如何摆放、绑定、显示和切换状态 |
| `assets/sounds/**` | 识别受支持的声音，建立目录索引及类型化声音引用 | 哪个行为或事件发声，以及音量等参数 |
| `prefabs/**` | 后续建立符合明确导出接口的可复用定义目录 | 是否实例化、实例数量和参数 |
| `scenes/**` | 后续作为可选择的场景定义 | 使用哪个场景、场景内的实例及关系 |
| `shared/**` | 普通作者代码，继续显式 import | 类、函数、工具与依赖 |

首轮只实现图片和声音目录，物体和场景的自动装配分开验证。可复用定义存在于目录中，不意味着创建一份游戏物体。动画可引用目录中的图片帧与声音；动画如何绑定行为仍由场景或模板明确表达，不从文件名推断触发时机。

“自动加载”首先表示资源被发现、编目并可供引用；项目生成时将场景使用和显式保留的资源交给现有数据校验与模拟，旧项目中未使用的资源仍保留。浏览器解码、声音播放与物体实例创建不是扫描目录时的隐含动作。

## 作者看到的接口

目录示例（prefabs/scenes 的自动装配仍未实现）：

```text
assets/
  images/street/bus.png
  sounds/street/brake.ogg
prefabs/
  bus.ts
scenes/
  commute.ts
shared/
  traffic.ts
```

当前 API；新生成的 ProjectContext 注入 assets：

```ts
scene.image('bus-view', context.assets.images.street.bus)
  .bind(objects.bus);
```

手写项目只需建立一次目录依赖，无需逐项声明资源：

```ts
import { createAssets } from '@gothere/assets';
const assets = createAssets(level);
scene.image('bus-view', assets.images.street.bus);
```

源码窗口左栏展开「＋ 图片 / 音效」，可批量导入文件或目录，并填写可选子目录 `street`。文件根据类型归入图片或声音目录；选择 `assets`、`images`、`sounds` 文件夹会保留相应结构，其他文件夹保留文件夹名。一次最多32份，遇到无效文件整批不写入。仅索引资源不会播放音效或创建物体；导入时解码以验证尺寸和时长。音效在查看器手动播放。

目录和无后缀文件名转成属性：`city-bus.png` → `cityBus`，中文名称可用；属性重名、文件与子目录占同一个属性、不能转换的名称明确报错。`.gothere/assets.ts` 显示只读索引，不包含媒体字节。F12 / Ctrl+点击图片或声音引用直接打开资源预览，可返回原源码位置。图片、声音不会出现在入口选择中。

具体属性及类型由项目目录索引生成，不能退回 `assets.get('任意字符串')` 作为主要接口。作者不手写遍历、导入清单或巨大的返回对象。目录中的原文件可从引用处跳转查看，图片和声音由资源查看器显示，生成的索引只读。

资源首次导入由路径产生稳定标识，移动或重命名保留标识。编辑器用 TypeScript 定义查询更新完整的点号/字面量方括号目录引用，不修改注释或字符串；解构及目录别名等无法安全更新的引用会阻止移动并说明原因。删除资源保留源码，失效引用在校验时报告，可恢复之前的项目。内部元数据保持已有资源 ID、显示名、尺寸、扩展信息与导入顺序，不要求作者逐个手写清单。

## 与现有项目的衔接

版本1作者项目继续保存原来的 `.ts` / `.js` 文本，不自动重写。新生成或首次导入目录资源后使用版本2：源码与媒体分开存储。ZIP 包含源文件、原始媒体字节和编辑器维护的 `.gothere/project.json` 元数据；内置资源只保存引用，实际内容随离线编辑器提供。生成索引不导出为可编辑文件。旧 ZIP 仍按首个源码选择入口，资源 ZIP 明确记录入口。

旧项目继续按原方式运行。目录索引在编辑器内生成明确、确定顺序的模块及类型信息，交给已有后台编译和生成流程；运行与回放继续只使用展开数据。资源随项目 ZIP 保存，离线编辑器不依赖 CDN 或读取用户电脑上的任意目录。

沿用运行数据限制：最多24张自定义图片，单张256 KiB、最长边2048，自定义图片总计512 KiB；最多8个音效，单个256 KiB、最长8秒，声音总计约512 KiB。最多256个目录资源（含内置引用）；源码仍为256份、合计2 MiB，资源 ZIP 解压上限4 MiB，生成关卡上限1 MiB。已有素材 ID、图片/声音顺序、绑定、帧动画、反馈与自定义扩展保真；不能通过一次升级静默重新生成并覆盖手写项目。

目录索引按明确的字符顺序排序，不依赖文件选择或本机语言排序。导入资源单独记录顺序以保留已有 DSL 的数组顺序；重命名不改变顺序。未来种子分享的版本边界见 [种子复现约定](seed-sharing.md)。

## 首轮验收

1. 在项目资源目录添加图片或短音效后，立即出现可补全、可查看的类型化引用，无需修改资源注册代码。
2. 生成、临时试玩、应用、撤销及另存草稿沿用现有流程；资源可用不改变已有玩法或自动新增物体。
3. 添加、删除、重命名与重名冲突有明确反馈；失效引用在应用前报告。
4. ZIP 导出再导入与离线打开均保留资源及引用，旧 TS/JS 项目继续通过回归。

目录扫描转换为静态导入是一种成熟思路，可参考 [Vite Glob Import](https://vite.dev/guide/features#glob-import)。该语法属于 Vite 扩展；本编辑器的作者项目需实现自己的目录索引，不将其当作浏览器或 TypeScript 原生能力，也不因此要求迁移整个应用的构建工具。
