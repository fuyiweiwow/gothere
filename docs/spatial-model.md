# 空间模型实验：地面纵深与离地高度

日期：2026-11-04。分支：`codex/spatial-2-5d`。基线：主线 `88a08fc4e64c418e69d306b6831007868c02c49a`。本文件是待实现的规格，不代表编辑器已经支持以下功能。

## 要解决的问题

当前横版内核以 x 表达左右，以 y 表达高低；路面是沿横向的支撑线，人物方向只有左右。资源的图层顺序改变绘制次序，不能表达物体在地面上的前后位置。游乐场和街道中通往远处的路线因此容易被误做成斜坡。

本轮目标是可编辑的有限 2.5D 空间：人物仍自动沿作者安排的路线前进，玩家通过环境干预解谜。参考录像的证据范围见 [梦游先生研究档案](../references/snoozleberg/README.md)，不宣称已经掌握原关卡全部路线和碰撞规则。

## 必须成立的语义

- **位置与画面分离**：世界位置分别表达横向 x、地面纵深 depth 与离地高度 height。字段名和 schema 迁移方案在实现前由兼容测试确定；不能直接把旧 y 改名为 depth。
- **投影只负责显示**：第一步采用可配置的固定斜投影。相同高度向远处走会在画面上向上，升高也会向上，但两者的逻辑状态、接触和支撑不同。缩放、平移或更换投影不能改变模拟结果。
- **路线连接显式编辑**：路线节点和线段在世界空间中连接；画面交叉、不同高度的重叠都不会自动连接。离开支撑继续执行下落；不会为了到达目标自动寻路或等待。
- **接触与支撑使用世界几何**：画面上两个图形重叠不等于接触。同一位置的高架与地面分别提供支撑；车辆驶过桥下不能仅因投影重叠伤害桥上的人物。触发区同样需要明确纵深与高度范围。
- **遮挡和碰撞分离**：依据地面位置及物体空间关系组织前后遮挡；美术偏移、图片尺寸与手工绘制层级不能变成碰撞坐标。高架、地面与人物需要分别验证，不能仅按屏幕 y 排序宣称完成。
- **资源继续可创作**：普通资源可绑定人物、物体或路面，在空间锚点上叠加图片偏移、大小与动画。前后朝向允许选用不同资源；第一版不自动生成角色转身动画。
- **行为与事件继续通用**：空间中的移动、转向、到达、接触与支撑变化须有明确数据语义。不能通过关卡 ID、特定物体名称、隐藏传送或定时成功伪造路线。

## 最小验证场景

一张灰盒同时布置近侧人行道、向远侧延伸的连接路、远侧道路、移动车辆与一段高架。只使用足以检查空间关系的形状和配色，保留逻辑/资源两种编辑视图。

| 验证 | 必须看到的结果 |
| --- | --- |
| 横向后转入纵深 | 沿显式相连的路径走向远侧，再向外返回；同一地面上的 height 不因投影上下变化而改变 |
| 路线在画面交叉 | 未连接的路线不能直接换路；改变节点连接后才能进入另一条路线 |
| 前后遮挡 | 人物经过普通物体前后时遮挡关系相应改变；资源大小变化不改变脚点和碰撞 |
| 接触危险物 | 同一地面位置及相交高度范围内能够触发；仅画面重叠或处于另一纵深时不能误触发 |
| 桥上与桥下 | 地面车辆不误伤桥上人物；离开高架支撑后按世界高度下落，只有落到真实支撑才停止 |
| 修改与重放 | 改路线节点、纵深和高度后重新校验；保存/导入、暂停/单步、回放与离线执行保持同一结果 |
| 旧稿兼容 | 原里程碑 JSON 与行为无需手工改写，通关、失败、事件和表现回放保持原有结果 |

## 实施顺序与边界

先建立旧文档兼容与世界坐标/投影独立的测试，再实现路线、支撑、接触和可观察快照；之后接入投影渲染、资源锚点、遮挡，以及编辑器的选取、拖动、吸附和保存。最后用上面的场景验证完整创作链路。

是否沿用 schemaVersion 1、怎样扩展路面几何、如何迁移旧资源锚点，都是实现时必须明确的兼容决策，当前不提前声称已完成。有限路线不等于自由导航；固定投影也不等于完整透视或任意 3D。完整刚体物理、车辆 AI、生成算法及大规模主题地图不属于本轮。
